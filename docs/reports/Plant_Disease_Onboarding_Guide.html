Chapter 01

Welcome & Project Overview

What this project is and why you are reading this guide.

Welcome to the team! This document will walk you through everything you need to understand about this project — from the original idea to every line of important code. No prior deep learning experience is assumed. By the time you finish this guide you will be able to understand, run, and improve the system.

What does this project do?

In one sentence: you take a photo of a plant leaf, and the system tells you what disease it has and how to treat it.

The system does this in two steps. First it identifies what type of plant the leaf belongs to. Then it passes that information to a specialist model that knows the diseases for that specific plant. The final output includes the disease name, a confidence percentage, treatment advice, and a heatmap showing which part of the leaf the AI was looking at.

Chapter 02

The Problem We Solve

Why this project exists and what real-world pain it addresses.

The situation

Imagine a farmer in rural India or anywhere in the world. Their crops are getting sick — leaves are turning yellow, showing dark spots, wilting. If they don't identify the disease fast and treat it correctly, they can lose their entire harvest. The Food and Agriculture Organisation estimates that plant diseases cause 20–40% of global crop losses every year — worth over USD 220 billion.

The traditional solution and its problems

Expensive
Expert agronomist consultations cost money most small farmers don't have
Slow
Getting an expert to visit can take days — by then, disease spreads further
Unavailable
Many rural areas have no local agricultural experts at all
Inconsistent
Different experts sometimes give different diagnoses for the same disease

Our solution

An AI system that can look at a photo of a sick leaf and tell you exactly what disease it has — within seconds, from any computer, for free. The pipeline also gives treatment advice, so the farmer knows what to do immediately.

Technologies Used

Every tool in this project explained from zero, no jargon.

Python

The programming language everything is written in. All our code — building models, processing images, showing results — is Python. We use Python 3.13.

TensorFlow & Keras

TensorFlow is Google's open-source library for building and training AI models — think of it as the engine. Keras is a friendlier interface that sits on top of TensorFlow and is now part of it — it's the steering wheel that makes the engine easy to use. When you see model.fit() or model.predict(), that is Keras.

Important: This project uses Keras 3 (which comes with recent TensorFlow versions and Python 3.13). Some older code patterns don't work in Keras 3. All code in this project has been updated to be Keras 3 compatible.

MobileNetV2

A pre-built neural network designed by Google and trained on 14 million images. We borrow its learned visual knowledge and re-train just the final layers to recognise plant diseases. This technique is called transfer learning — explained fully in Chapter 4.

NumPy

A library for fast mathematics on large arrays of numbers. When an image is loaded, it becomes a 3-dimensional grid of numbers (pixels). NumPy lets us do fast calculations on those numbers.

Matplotlib & PIL (Pillow)

Matplotlib draws graphs and charts — we use it to show confidence bar charts and Grad-CAM heatmaps. PIL/Pillow opens, resizes, and converts image files between formats.

OpenCV (cv2)

A computer vision library used for image preprocessing improvements — specifically for isolating the dominant leaf region from complex real-world photographs with cluttered backgrounds.

ipywidgets

A library that adds interactive UI elements inside Jupyter notebooks — buttons, sliders, dropdowns, file uploaders. We use it to create the upload button interface in the main notebook.

Jupyter Notebook

The environment where all the code runs. Think of it as a document where you can write and run code cell by cell, see outputs immediately, and add explanatory text between cells. All .ipynb files are Jupyter notebooks.

Chapter 04

Deep Learning 101

Neural networks, training, and transfer learning — explained plainly.

What is a neural network?

A neural network is a program that learns from examples. Instead of writing rules like "if the leaf has brown spots, it is Early Blight", we show it thousands of labelled photos and let it figure out the rules itself. It is called "neural" because it is loosely inspired by how brain cells (neurons) connect together.

What does "training" mean?

Training is the process of showing the network labelled examples over and over. Each time it makes a wrong prediction, it adjusts its internal numbers (called weights) a tiny bit to do better next time. After thousands of adjustments across thousands of images, it gets good at the task.

Epoch 1:  train accuracy = 96.6%   val accuracy = 94.7%   ← still learning
Epoch 5:  train accuracy = 99.1%   val accuracy = 96.6%   ← getting better
Epoch 10: train accuracy = 99.5%   val accuracy = 93.8%   ← converged
Why does val accuracy fluctuate? Training accuracy measures performance on data the model has seen. Validation accuracy measures it on unseen data. The gap between them tells us how well the model generalises to new photos.

What is transfer learning?

Training a neural network from scratch takes millions of images and weeks of computing time. Transfer learning is a shortcut: we take a network already trained on a huge general dataset, and re-use its learned visual features for our specific task.

Analogy: If you already know how to drive a car, learning to drive a truck is much faster than learning from zero. You re-use your existing "driving knowledge" and just adapt to the new vehicle. That is exactly what we do — we take MobileNetV2's "visual knowledge" and adapt it to recognise plant diseases.

What is MobileNetV2?

MobileNetV2 is a neural network architecture designed by Google in 2018. "Mobile" means it is optimised to be fast and lightweight — it can run on a phone without needing a powerful GPU. It was trained on ImageNet (14 million images, 1000 categories). So it already "knows" how to see edges, textures, colours, and complex patterns. We add our own classification layers on top.

Our model structure

Input
Leaf image 224×224×3
3 colour channels (RGB), resized to model input size
↓
MobileNetV2 backbone — frozen
Feature extraction
154 layers, pretrained on ImageNet — outputs 7×7×1280 feature maps
↓
GlobalAveragePooling2D
Spatial compression
Converts 7×7×1280 → flat vector of 1280 numbers
↓

Pattern learning

↓

N = number of classes. Outputs probability for each class summing to 1.

What does softmax output mean?

The output is a list of probabilities — one number per class, all adding up to 1. For the plant model the output might be: Apple=0.96, Corn=0.02, Grape=0.01, Pepper=0.005, Potato=0.004, Tomato=0.001. We pick the highest one — Apple at 96%.

What is data augmentation?

When we don't have enough images, we artificially create more by slightly modifying the existing ones — rotating them, flipping them, zooming in slightly. The model then sees more variety and becomes more robust to real-world photos.

from tensorflow.keras.preprocessing.image import ImageDataGenerator

train_datagen = ImageDataGenerator(
    rescale=1./255,          # normalise pixels to [0,1]
    rotation_range=20,       # rotate up to 20 degrees
    zoom_range=0.2,          # zoom in/out up to 20%
    horizontal_flip=True    # randomly mirror the image
)

Training vs validation split

We never test the model on data it trained on — that would be like letting a student take the same exam they studied from. The validation set contains images the model has never seen, so accuracy on it reflects real-world performance.

Known limitation: dataset vs real world

PlantVillage images were taken under controlled conditions — one leaf, plain background, good lighting. Real field photos have multiple leaves, dark backgrounds, shadows, and glare. This is why we added an improved preprocess_image() function that isolates the dominant leaf using OpenCV before feeding the image to the model.

Chapter 06

Two-Stage Architecture

The most important design decision in the whole project.

Why not just one big model?

A simple approach would be: train one model that takes a leaf image and directly outputs "Apple Scab" or "Grape Black Rot" — one model covering all 13+ disease classes. The problem is that a single model trying to do everything gets confused. It has to learn "is this an apple or a grape?" at the same time as "is this scab or black rot?" — these are very different visual tasks mixed together.

Our approach: divide and specialise

Input
Any leaf image (photo from camera or file)
↓
Stage 1 — plant_identifier.keras
"What plant is this?"
Outputs one of: Apple / Corn / Grape / Pepper / Potato / Tomato
↓
DISEASE_REGISTRY routing
Auto-select the right disease model
Apple → Apple model  |  Potato → Potato model  |  etc.
↓
Apple model
4 classes
Potato model
3 classes
Grape model
4 classes
Pepper model
2 classes
↓
Output
Disease name + Confidence % + Treatment advice + Grad-CAM heatmap

Advantages of this design

AdvantageWhat it means in practice
Each model is a specialistThe Apple model only knows about apple diseases — it is sharper than a generalist
Easy to extendAdding Tomato diseases? Just train a Tomato model and add one line to DISEASE_REGISTRY
Fail gracefullyIf no disease model exists, Stage 1 still tells you what plant it is
Separate improvementYou can improve the Grape model without touching Apple or Potato
Faster per-model trainingEach specialist model trains on a smaller focused dataset — faster and more accurate

The Pepper exception

Pepper was accidentally left out of the Stage-1 training data. So for Pepper, we use a plant_override parameter to skip Stage 1 and go directly to the Pepper disease model. This is handled cleanly in the code:

# Normal use — Stage 1 detects the plant automatically
show_combined("apple_leaf.jpg")

# Pepper override — skip Stage 1
show_combined("pepper_leaf.jpg", plant_override="Pepper")

The DISEASE_REGISTRY

This Python dictionary is the routing table of the entire pipeline. It maps plant names to their models and class labels:

Each Model Explained

A detailed look at the architecture of all five trained models.

plant_identifier.keras — Stage 1 Sequential API

Trained in Plant_Identification.ipynb. Classifies leaf images into 6 plant categories. Uses a Sequential Keras model (layers stacked in a simple line, one after another).

model = Sequential([
    MobileNetV2(weights='imagenet', include_top=False),
    GlobalAveragePooling2D(),
    Dense(128, activation='relu'),
    Dense(6, activation='softmax')   # 6 plant classes
])
MetricValue
Best validation accuracy96.61% (epoch 5)
Final training accuracy99.53%
Epochs trained10
Output classesApple, Corn, Grape, Pepper, Potato, Tomato

Apple_disease.keras — Stage 2-A Functional API

Trained in Apple_disease.ipynb. Uses the Functional API (more flexible than Sequential — allows complex connections). Also includes BatchNormalization and Dropout for better generalisation, and was fine-tuned in two phases.

inputs = Input(shape=(224, 224, 3))
x = base_model(inputs, training=False)
x = GlobalAveragePooling2D()(x)
x = BatchNormalization()(x)    # stabilises training
x = Dense(256, activation='relu')(x)
x = Dropout(0.4)(x)           # prevents overfitting
x = Dense(128, activation='relu')(x)
x = Dropout(0.3)(x)
outputs = Dense(4, activation='softmax')(x)
BatchNormalization normalises the activations between layers so training is more stable. Dropout randomly "turns off" some neurons during training, which forces the network to learn more robust features and prevents memorising the training data.

Potato / Grape / Pepper models — Stage 2-B, C, D

All follow the same MobileNetV2 backbone pattern. The only difference is the number of output classes:

Critical: class labels must match model outputs

Your class label list must have exactly the same number of items as the model's output neurons, and in the same alphabetical order that ImageDataGenerator assigned during training. To verify this, run:

Key functions explained

preprocess_image( )

Every image must be converted to the same format before feeding to the model. Steps: load with OpenCV → convert to HSV colour space → create a green-pixel mask → find the largest contour (dominant leaf) → crop to that region with 10% padding → resize to 224×224 → apply MobileNetV2 normalisation (scales pixels from [0,255] to [-1,1]).

run_pipeline( )

The glue function. Takes an image path and optional plant_override. Calls identify_plant() to get the plant name, then calls detect_disease() with that plant name to get the disease. Returns a single result dictionary with keys: plant, disease, plant_confidence, disease_confidence, advice.

show_combined( )

The main display function. Calls run_pipeline(), generates Grad-CAM heatmaps for both stages, then draws a 2-row 4-column figure: original image, Stage-1 heatmap, Stage-2 heatmap, pure activation map (row 1) and Stage-1 confidence bars, Stage-2 confidence bars, treatment advice (row 2).

Chapter 09

Grad-CAM Heatmaps

What they are, why we added them, and how they work.

Why we need explainability

When the model says "This is Apple Scab (94% confidence)", how do we know it is looking at the right part of the leaf and not accidentally at the background colour or a watermark? We can't trust what we can't inspect. Grad-CAM solves this by showing exactly which pixels drove the prediction — overlaid as a colour heatmap on the original image.

How to read the heatmap

Colour (jet colourmap)Meaning
Red / YellowHighest activation — the region that most influenced the prediction
GreenMedium influence on the prediction
BlueLow influence — model largely ignored this area

For a diseased leaf, the red zone should fall on the lesion or spot area. If it falls on the background or stem, the model may have learned the wrong features — a useful signal for improving your training data.

How Grad-CAM works (step by step)

  1. Hook into the last conv layer
    We access the out_relu layer inside MobileNetV2. This outputs a 7×7×1280 tensor — 1280 feature maps, each 7×7 pixels. These represent what the model "sees" in the image.
  2. Compute gradients
    Using tf.GradientTape, we measure how much each position in those feature maps influenced the predicted class score. Large gradient = that area was important.
  3. Pool and weight
    We average the gradients over space (Global Average Pooling) to get one importance score per channel. Then we multiply each of the 1280 feature maps by its importance score and sum them all together.
  4. Apply ReLU and normalise
    Keep only positive values (areas that pushed the score upward) and normalise to [0,1]. This gives a 7×7 heatmap.
  5. Upsample and overlay
    Resize the 7×7 heatmap to 224×224 using bilinear interpolation. Apply the jet colour map. Blend over the original image at 45% opacity.

Keras 3 compatibility note

The standard Grad-CAM implementation uses model.output to build a gradient model. This fails in Keras 3 for Sequential models because they don't populate _inbound_nodes until called. Our implementation avoids this by:

  1. Finding the MobileNetV2 sub-model
    MobileNetV2 is always a Functional model — we can safely build a sub-model from its input to the target conv layer.
  2. Watching conv outputs explicitly
    We run the feature extractor separately, call tape.watch(conv_outputs), then manually thread through remaining layers.
  3. Computing gradients cleanly
    Gradients of class_score with respect to conv_outputs flow through the explicit layer calls, giving correct Grad-CAM results without touching model.output.

Chapter 11

Common Errors & Fixes

Every error you are likely to encounter and exactly how to fix it.

Error 1: FileNotFoundError on model load

FileNotFoundError: ... Apple_disease.keras not found

Cause: The model file is not in the same folder as the notebook.

Fix: Move all five .keras files to the same folder as Plant_DISEASE_Main.ipynb.

Error 2: Shape mismatch in confidence bar chart

Error: shape mismatch — arg 2 shape (6,) and arg 3 shape (5,)

Cause: Your class label list has a different number of items than the model's output neurons.

Fix: Run the diagnostic cell from Chapter 7 to find which list is wrong. ImageDataGenerator assigns classes alphabetically, so your labels list must be in exact alphabetical order. For Stage-1: ["Apple", "Corn", "Grape", "Pepper", "Potato", "Tomato"] (6 items matching 6 model outputs).

Error 3: AttributeError on model.output (Keras 3)

AttributeError: The layer sequential_1 has never been called
and thus has no defined output.

Cause: In Keras 3, Sequential models don't expose model.output until called. The old Grad-CAM code used this property.

Fix: Use the updated get_gradcam_heatmap() from Step 5-A which avoids model.output entirely by manually threading through remaining layers.

Error 4: Gradient is None in Grad-CAM

RuntimeError: Gradient is None — the conv layer output is not
connected to the class score.

Cause: The last_conv_layer_name specified doesn't exist in the model, or the layer name has changed.

Fix: Run this to find the correct layer name:

base = _find_mobilenet_base(plant_model)
# Look for the last layer with 'relu' in its name
for layer in base.layers[-10:]:
    print(layer.name, layer.output_shape)

Error 5: Low confidence warning

⚠ Low confidence (32.4%) — result may be unreliable

Cause: The uploaded image quality is poor, contains multiple leaves, or the plant is not in the training set.

Fix: Follow the photography tips in Chapter 10. Make sure the leaf fills most of the frame with a plain background. The system still returns its best guess but warns you to treat it with caution.

Error 6: cv2 not found

ModuleNotFoundError: No module named 'cv2'

Fix:

pip install opencv-python
Chapter 12

Glossary

Every technical term in this project, explained in plain language.

Epoch
One complete pass through all training images. Training for 10 epochs means the model sees every image 10 times, adjusting its weights each time.
Accuracy
The percentage of images the model classified correctly. 99% means it gets 99 out of 100 right.
Validation accuracy
Accuracy on images the model has never seen during training. This is the real measure of how well the model will work in the real world.
Overfitting
When a model memorises the training data instead of learning general patterns. It performs great on training images but poorly on new images. Dropout and BatchNorm help prevent this.
Dropout
A training technique that randomly turns off some neurons during each step. Forces the network not to rely on any single neuron — makes it more robust.
BatchNormalization
Normalises the output of a layer so values stay in a reasonable range. Makes training faster and more stable by preventing values from getting too large or too small.
Softmax
An activation function in the last layer that converts raw numbers to probabilities that sum to 1. Used so outputs are interpretable as confidence percentages.
ReLU
Rectified Linear Unit. An activation function: output = max(0, input). Without activation functions, a neural network would just be doing linear algebra and couldn't learn complex patterns.
Weights
The internal numbers of a neural network that get adjusted during training. A trained model is essentially a very large set of well-tuned weights — millions of them.
.keras file
The saved model file. Contains both the architecture (layer structure) and the trained weights. Load it with tf.keras.models.load_model("file.keras").
Transfer learning
Re-using a model trained on one task (e.g. 14 million general images) as a starting point for a new related task (e.g. plant diseases). Much faster and requires far less data than training from scratch.
Fine-tuning
Phase 2 of transfer learning: unfreeze some of the base model's layers and retrain them at a very low learning rate so they adapt slightly to your specific domain.
Frozen layers
Layers whose weights are not updated during training. We freeze MobileNetV2's base to preserve its pre-learned visual knowledge and only train our custom head.
preprocess_input
A function from Keras that scales pixel values from [0–255] to [−1, 1], which is what MobileNetV2 was trained to expect. Skipping this step causes significantly worse accuracy.
Grad-CAM
Gradient-weighted Class Activation Mapping. A technique to visualise which parts of an input image caused a neural network to make its prediction. The output is a colour heatmap overlaid on the original image.
GradientTape
A TensorFlow tool that records operations as they execute, allowing gradients to be computed afterwards. Used in Grad-CAM to measure how much each pixel influenced the output class score.
Feature map
The intermediate output of a convolutional layer — a set of 2D grids, each one detecting a different visual feature (edges, textures, colours, patterns) at different positions in the image.
DISEASE_REGISTRY
A Python dictionary that maps plant names to their disease models and class label lists. The routing table of the entire pipeline. Adding a new plant requires only one new entry here.
ImageDataGenerator
A Keras utility that loads images from folders and applies augmentation on the fly during training. Assigns class indices alphabetically based on folder names — this alphabetical order must match your class labels list.
ipywidgets
A Python library for adding interactive UI elements (buttons, sliders, file uploaders) to Jupyter notebooks. We use it for the upload button interface in the main notebook.
Sequential vs Functional API
Two ways to build Keras models. Sequential stacks layers in a simple line. Functional is more flexible and allows complex connections. Our plant identifier uses Sequential; the Apple model uses Functional.
